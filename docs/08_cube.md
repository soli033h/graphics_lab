# 08. 3D 큐브 렌더링

현재 [src/main.cpp](../src/main.cpp)는 창을 생성하고 화면을 지우는 단계입니다.
이 문서는 이 상태에서 출발해 **3차원 큐브를 화면에 표시하기 위해 필요한 개념과 순서**를 설명합니다.

이번 단계의 목표는 텍스처나 조명보다 먼저, 큐브의 3D 구조와 깊이 처리를 이해하는 것입니다.

```text
창 생성
    ↓
삼각형 렌더링
    ↓
사각형과 EBO
    ↓
3D 좌표와 큐브
    ↓
카메라와 원근
    ↓
법선과 조명
```

## 1. 큐브는 6개의 면으로 구성된다

큐브에는 다음 6개의 면이 있습니다.

```text
앞면
뒷면
왼쪽 면
오른쪽 면
위쪽 면
아래쪽 면
```

각 면은 사각형이고, OpenGL은 사각형을 직접 그리지 않고 삼각형으로 그립니다.
따라서 큐브는 다음과 같이 구성됩니다.

```text
6개 면
    ×
면 하나당 2개 삼각형
    =
12개 삼각형
```

삼각형마다 정점 3개가 필요하므로, 가장 단순하게 작성하면:

```text
12개 삼각형 × 3개 정점 = 36개 정점
```

## 2. 3D 정점 좌표

2D 정점은 보통 다음처럼 `x`, `y`만 저장했습니다.

```text
x, y
```

3D 정점에는 깊이를 나타내는 `z`가 추가됩니다.

```text
x, y, z
```

큐브를 원점 주변에 배치한다면 각 축의 좌표를 `-0.5`와 `0.5`로 구성할 수 있습니다.

```text
앞면: z =  0.5
뒷면: z = -0.5
```

개념적으로 앞면의 네 꼭짓점은 다음과 같습니다.

```text
(-0.5,  0.5,  0.5)  왼쪽 위
( 0.5,  0.5,  0.5)  오른쪽 위
( 0.5, -0.5,  0.5)  오른쪽 아래
(-0.5, -0.5, 0.5)   왼쪽 아래
```

나머지 면도 같은 방식으로 `x`, `y`, `z`의 부호를 조절해 만듭니다.

## 3. 왜 정점을 재사용하기 어려운가?

큐브의 기하학적 꼭짓점만 세면 `2 × 2 × 2 = 8개`입니다.
그러나 실제 렌더링에서는 한 꼭짓점이 면마다 다른 데이터를 가질 수 있습니다.

예를 들어 하나의 모서리에 만나는 세 면은:

* 서로 다른 텍스처 좌표를 가질 수 있고
* 서로 다른 법선 벡터를 가질 수 있습니다.

따라서 다음 두 방식이 가능합니다.

### 가장 단순한 방식: 36개 정점

```text
각 면의 정점을 따로 작성
    ↓
면마다 UV와 법선을 독립적으로 지정
```

처음 큐브를 구현할 때 추천하는 방식입니다.

### 정점 재사용 방식: 8개 또는 24개 정점

EBO로 정점을 재사용할 수 있지만, 위치만 같은 정점이라도 면별 UV나 법선이 다르면 분리해야 합니다.
그래서 텍스처와 조명까지 고려하면 보통 24개의 정점을 사용합니다.

```text
6개 면 × 면당 4개 정점 = 24개 정점
```

핵심은 **정점의 위치가 같다고 해서 모든 정점 속성이 같은 것은 아니다**라는 점입니다.

## 4. 버텍스 셰이더의 3D 입력

2D 버텍스 셰이더는 보통 다음과 같습니다.

```glsl
layout (location = 0) in vec2 position;

void main()
{
    gl_Position = vec4(position, 0.0, 1.0);
}
```

3D에서는 입력을 `vec3`로 바꿉니다.

```glsl
layout (location = 0) in vec3 position;
```

그리고 `z`를 직접 버리지 않고 `vec4`에 포함합니다.

```glsl
gl_Position = vec4(position, 1.0);
```

하지만 이 방식만으로는 큐브가 입체적으로 보이지 않습니다.
카메라와 원근을 적용하려면 모델, 뷰, 투영 행렬이 필요합니다.

## 5. 모델·뷰·투영 행렬

3D 정점은 여러 좌표 공간을 거칩니다.

```text
로컬 공간
    ↓ Model
월드 공간
    ↓ View
카메라 공간
    ↓ Projection
클립 공간
    ↓
화면
```

### 모델 행렬(Model)

물체 자체의 위치, 회전, 크기를 결정합니다.

```text
Model
    → 큐브를 회전
    → 큐브를 이동
    → 큐브의 크기 조절
```

### 뷰 행렬(View)

카메라의 위치와 방향을 반영합니다.

```text
View
    → 카메라가 어디에 있는가?
    → 어느 방향을 바라보는가?
```

### 투영 행렬(Projection)

3D 공간을 2D 화면에 투영하는 방식을 결정합니다.

```text
Projection
    → 원근 투영
    → 직교 투영
```

셰이더에서의 일반적인 최종 계산은 다음과 같습니다.

```glsl
gl_Position = projection * view * model * vec4(position, 1.0);
```

행렬은 오른쪽의 정점부터 적용된다고 이해하면 됩니다.

```text
position
    ↓ model
월드 공간
    ↓ view
카메라 공간
    ↓ projection
클립 공간
```

## 6. 큐브를 카메라 앞에 배치하기

카메라가 원점에서 `-z` 방향을 바라본다고 가정하면, 큐브는 카메라 앞쪽에 있어야 합니다.

```text
카메라: z = 0
큐브:   z = -3
```

이 위치는 모델 행렬 또는 뷰 행렬의 이동으로 만들 수 있습니다.

```text
큐브를 뒤쪽으로 이동
    → z 방향 이동값을 음수로 설정
```

큐브가 화면에 보이지 않는다면 다음을 확인해야 합니다.

* 큐브가 카메라 뒤에 있지 않은가?
* 투영 행렬의 near/far 범위 안에 있는가?
* `gl_Position`에 `z`를 전달하고 있는가?
* 행렬 곱셈 순서가 올바른가?

## 7. 원근 투영

원근 투영에서는 멀리 있는 물체가 작게 보입니다.

```text
카메라에 가까운 큐브 면
    → 크게 보임

카메라에서 먼 큐브 면
    → 작게 보임
```

원근 투영을 만들 때 주로 다음 값을 사용합니다.

```text
field of view
aspect ratio
near clipping plane
far clipping plane
```

특히 화면의 가로세로 비율은 중요합니다.

```text
aspect ratio = 창 너비 / 창 높이
```

창 크기에 맞는 aspect ratio를 사용하지 않으면 큐브가 가로 또는 세로로 늘어나 보일 수 있습니다.

## 8. 깊이 테스트

3D에서는 단순히 그리는 순서만으로 앞면과 뒷면을 판단할 수 없습니다.
각 프래그먼트의 깊이를 저장하는 **깊이 버퍼(depth buffer)**가 필요합니다.

초기화 시 깊이 테스트를 활성화합니다.

```cpp
glEnable(GL_DEPTH_TEST);
```

렌더링 루프에서는 색상 버퍼와 깊이 버퍼를 함께 지워야 합니다.

```cpp
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
```

깊이 테스트의 흐름은 다음과 같습니다.

```text
프래그먼트 생성
    ↓
현재 깊이 값과 비교
    ↓
더 가까우면 그리기
더 멀면 버리기
    ↓
깊이 버퍼 갱신
```

`glClear`에 `GL_DEPTH_BUFFER_BIT`를 빠뜨리면 이전 프레임의 깊이 정보가 남아 다음 프레임의 렌더링을 방해합니다.

## 9. 면의 방향과 정점 순서

삼각형의 정점 순서는 면이 향하는 방향을 결정하는 데 사용됩니다.
OpenGL의 기본 앞면 기준은 반시계 방향(counter-clockwise)입니다.

```text
반시계 방향
    → 앞면으로 취급
시계 방향
    → 뒷면으로 취급될 수 있음
```

면 제거를 활성화하면 뒷면을 그리지 않을 수 있습니다.

```cpp
glEnable(GL_CULL_FACE);
glCullFace(GL_BACK);
```

처음에는 면 제거를 사용하지 않고 큐브를 확인하는 것도 좋습니다.
면이 사라질 때는 먼저 각 면의 정점 순서가 올바른지 확인해야 합니다.

## 10. 큐브 회전

정적인 큐브가 보이면 시간에 따라 모델 행렬을 변경해 회전시킬 수 있습니다.

```text
프레임마다:
    현재 시간 읽기
    회전 각도 계산
    model 행렬 생성
    model uniform 전달
    큐브 그리기
```

예를 들어 y축 회전은 큐브의 좌우 면이 번갈아 보이게 합니다.

```text
angle = glfwGetTime() * rotation_speed
```

회전 행렬은 CPU에서 직접 만들거나 GLM과 같은 수학 라이브러리를 사용할 수 있습니다.
현재 프로젝트에서는 먼저 직접 만든 행렬의 구조를 이해한 뒤 라이브러리를 사용하는 방식이 학습에 도움이 됩니다.

## 11. 텍스처와 조명은 언제 추가하는가?

큐브 자체가 표시된 뒤에 텍스처를 추가합니다.

```text
position
    + texture coordinate
```

조명까지 추가하면 법선 벡터가 필요합니다.

```text
position
    + texture coordinate
    + normal
```

최종적으로 한 정점의 데이터는 다음처럼 구성될 수 있습니다.

```text
x, y, z, nx, ny, nz, u, v
```

추천 순서는 다음과 같습니다.

```text
1. 단색 큐브
2. 회전하는 단색 큐브
3. 텍스처가 적용된 큐브
4. 법선 벡터 추가
5. Diffuse 조명
6. Ambient와 Specular 조명
```

## 12. 구현 체크리스트

큐브를 구현할 때 다음 순서로 확인하면 좋습니다.

```text
□ 위치를 vec3로 변경
□ 6개 면의 정점 작성
□ 12개 삼각형 구성
□ 버텍스 셰이더에서 z 좌표 사용
□ model, view, projection uniform 선언
□ 투영 행렬의 aspect ratio 계산
□ 큐브를 카메라 앞쪽으로 이동
□ glEnable(GL_DEPTH_TEST) 호출
□ glClear에 GL_DEPTH_BUFFER_BIT 추가
□ 행렬 곱셈 순서 확인
□ 각 면의 정점 순서 확인
□ 정적 큐브가 보인 뒤 회전 추가
```

## 13. 자주 발생하는 문제

### 큐브가 전혀 보이지 않는 경우

```text
카메라 뒤에 배치됨
행렬이 전달되지 않음
투영 범위 밖에 있음
gl_Position의 w 값이 잘못됨
```

먼저 행렬을 모두 항등 행렬로 두고, 큐브가 클립 공간 안에 있는지 확인합니다.

### 큐브가 평면처럼 보이는 경우

```text
z 좌표가 적용되지 않음
view 또는 projection 행렬이 빠짐
모든 면의 좌표가 같은 평면에 있음
```

### 면이 이상하게 사라지는 경우

```text
정점 순서가 반대임
면 제거 설정과 winding 방향이 맞지 않음
```

### 화면이 깜빡이거나 면이 겹쳐 보이는 경우

```text
깊이 테스트가 꺼져 있음
깊이 버퍼를 매 프레임 지우지 않음
```

## 핵심 요약

```text
큐브
    = 6개 사각형
    = 12개 삼각형
```

```text
3D 정점
    → vec3 position
    → Model 행렬
    → View 행렬
    → Projection 행렬
    → gl_Position
```

```text
깊이 테스트 활성화
    + 깊이 버퍼 초기화
    = 앞·뒤 면을 올바르게 표시
```

큐브 렌더링의 첫 번째 목표는 **회전이나 조명보다 먼저, 카메라 앞에 있는 단색 큐브가 깊이 테스트와 함께 올바르게 보이게 만드는 것**입니다.
